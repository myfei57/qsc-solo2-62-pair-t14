# 蒸发冷自适应基线 —— 设计决策记录（ADR）

状态：已定稿（2026-10-06）
影响组件：`coldstore/evap`、`coldstore/console`、遥测、报表、审计

## 1. 两个需要拍板的问题

### 1.1 基线按日滑动还是按小时滑动？—— 按小时滑动

结论：**每小时一个滑动修正 tick（hourly sliding），温度分箱内做时间衰减 EWMA，默认半衰期 14 天。**

理由：

- 基线的自变量是**环境温度**。一天之内环境温度就能跨越多个季节特征（清晨 8℃、午后 30℃），
  按日滑动意味着同一天午后的样本要到次日才被吸收，修正滞后一个完整昼夜。
- 按小时滑动不需要重算窗口：样本进箱时做一次 O(1) EWMA 更新，tick 只做陈旧检测和周轮换；
  14 天半衰期保证单次噪声和单日天气都不足以拉动基线，计算开销为
  每样本 O(1)、每 tick O(B)（B 为固定箱数，约 22 个箱）。
- 冬夏差异由**环境温度分箱**（2.5℃/箱，范围 -10℃～45℃，相邻箱线性插值）天然隔离：
  冬季样本和夏季样本落在不同箱里，永远不会互相污染，而不是靠滑动周期去“忘记”上一个季节。

不选日滑动的原因：日窗口在日内温差大时响应迟钝，而且要保留整天的原始样本做重算，
内存和 CPU 都随采样率增长；本设计每箱只有 4 个统计量（均值、方差、有效样本数、最后时间）。

### 1.2 超限是加大风机还是切备用？—— 切备用（先并机，恢复后再提升）

结论：**超限自动把健康备用风机并到值班风机上；恢复后停旧机、把备用提升为值班。不做“加大风机”。**

理由：

- 现场蒸发冷风机是单速风机对（primary/standby），没有调速档，“加大风机”在物理上没有执行器；
  能增加的冷量就是“多上一台整机”。
- 直接硬切（停值班、起备用）会在启停间隙造成瞬时风量空缺，对冷凝压力是最危险的动作；
  并机保证任何时刻风量不减少，恢复确认后再完成角色提升。
- 切换是离散、可审计的事件，适合进审计清单；调速是连续动作，既无执行器也难以审计。

动作时序：

1. 残差（冷凝温度 − 当前基线）超过 **预警余量 2℃** → `warn`，只记录；
2. 残差超过 **超限余量 4℃** 并持续 **60 秒去抖** → `over`，启动健康备用并机，发 `exceeded` 告警；
3. 超限持续超过 **5 分钟** → 每 5 分钟重复一条 `persistent-exceeded` 告警（不重复切机）；
4. 温度回落到「基线 + 预警余量 − 0.5℃ 迟滞」以下 → 停旧机、备用提升为值班，回到 `warn`；
5. 无健康备用可用时命令记为 `unavailable`，状态照进 `over`，告警照发（不能静默失败）；
6. 值班风机每周（168h，可配）在**正常状态**自动轮换一次；轮换锚点独立计时，
   超限/故障期间不轮换。

## 2. 采样管线（高频采样先限流，再进基线）

```
原始样本
  → 量程校验（环境 -40~60℃，冷凝 -50~80℃）
  → 令牌桶限流（默认 1 个/秒，突发 2）
  → 稳态门（环境斜率 ≤10℃/h、冷凝斜率 ≤20℃/h、风机档位未变；按温度箱独立记忆）
  → 统计门（离群点：|x − 箱均值| > 4·max(σ, 0.3℃)，或冷启动预热）
  → 判定始终执行；只有“稳态且非离群”的样本才允许学习基线
```

关键原则：**限流、非稳态、离群只会阻止样本污染基线，绝不阻止判定与保护动作。**
真实超限点相对刚学完的箱往往就是“统计离群点”，如果让离群门短路判定，超限就永远报不出来。

- 冷启动（箱内无数据，或距上次样本已超过约一个半衰期）按预热处理，直接接纳，
  避免新工况被旧窄方差永久拒之门外。
- 离群带使用稳健下限 `sigma_floor=0.3℃`：长期平稳运行时方差趋近 0，
  离群阈值不能跟着塌缩到 0。
- 稳态门按**温度箱**分别记忆上一点，冬季工况切到夏季工况不会被误判为“环境在爬坡”。

## 3. 基线口径：值班、遥测、报表只读同一个值

唯一基线入口是 `Condenser.baseline()`（内部为 `CondenserController.baseline_value()`）：

- 输入：当前环境温度（最近一个已通过限流的样本携带）；
- 计算：相邻温度箱均值线性插值，再按置信度与人工兜底值融合；
- 置信度：`min(1, 时间衰减后的有效样本数 / 40)`，≥0.95 为 `learned/good`，
  ≥0.5 为 `blended/suspect`，否则用人工兜底（`cold/fallback`）；
- 人工基线（`POST /evap/baseline`）不再直接充当判定线，而是**学习曲线冷启动期间的兜底值**；
- `/evap`（值班 JSON）、`/telemetry`（对外遥测）、`/report`（文本报表）、
  `/export/telemetry`（CSV）、审计明细，全部读这同一个函数，禁止任何一方自行计算。

环境温度超出箱范围（< -10℃ 或 > 45℃）时取边界箱值，质量降级为 `suspect`，不外推。

## 4. 计算开销

| 操作 | 成本 | 说明 |
| --- | --- | --- |
| 进一个样本 | O(1) | 令牌桶 + 斜率 + 单箱 EWMA，固定几次浮点运算 |
| 每小时 tick | O(B)，B≈22 且与采样率无关 | 仅陈旧检测、轮换、写一条审计快照 |
| 持久化体积 | 每箱 4 个数 + 控制态 1 个 JSON | 不保留任何原始样本序列 |

时间衰减 EWMA：`α = 1 − 0.5^(Δt / 半衰期)`，无样本时自然老化，无需扫描历史窗口。

## 5. 审计清单（append-only）

审计条目复用既有 `Auditor`（kind + JSON detail），新增 kind：

| kind | 触发时机 | detail 关键字段 |
| --- | --- | --- |
| `evap.baseline-hour` | 每个 hourly tick | `sliding=hourly`、baseline、quality、basis、ambient、temperature、threshold、residual、status、verdict、duty、running、accepted、rejected、actions、alarms |
| `evap.alarm` | 超限并机、持续超限、传感器失效 | 同上口径 + command + alarms |
| `evap.command` | 恢复提升等非告警动作 | baseline、duty、running、command |
| `evap.switch` | 人工切机 | duty、running |
| `evap.baseline-manual` | 人工设置兜底基线 | fallback、当时实际对外服务的 served 值 |
| `evap.config` | 参数调整 | 完整配置快照 |
| `evap.fault-clear` | 故障确认清除 | outcome |

高频正常样本不写审计（每秒一条会淹没清单）；限流/拒绝计数在每小时快照里汇总。
基线、值班状态、判定结果三者在同一条记录里，保证事后能用同一口径复盘。

## 6. 失效安全

- 距最后一个样本超过 `stale_seconds`（默认 120 秒）→ tick 将状态置 `fault`，
  **强制启动所有无故障蒸发冷风机**（最大风量），发 `sensor-fault`。
- 故障期间样本不参与判定；传感器恢复后故障**不自动清除**，
  需操作员在确认数据流新鲜后调 `POST /evap/fault-clear`。
- 人工切机同样先起后停（重叠 30 秒为 PLC 层约定，服务层记录切换命令）。

## 7. HTTP 接口

| 方法/路径 | 用途 |
| --- | --- |
| `POST /evap/sample` | 采样入参 `ambient, temperature, at(epoch 秒), fan_level`，返回基线、质量、残差、状态、判定、值班、命令、告警 |
| `POST /evap/tick` | 每小时滑动维护（生产由定时器调用；可传 `at`） |
| `GET /evap/config` / `POST /evap/config` | 参数查看/整定（带校验，非法值 400） |
| `GET /evap` | 值班统一状态视图 |
| `POST /evap/baseline` | 人工兜底基线（学习曲线冷启动前生效） |
| `POST /evap/switch` | 人工切备用 |
| `POST /evap/fault-clear` | 传感器故障确认 |
| `GET /telemetry`、`GET /report`、`GET /export/telemetry` | 同一口径的对外读数 |

## 8. 关键默认参数（全部可调）

| 参数 | 默认值 |
| --- | --- |
| 限流间隔 / 突发 | 1.0 秒 / 2 |
| 温度箱范围 / 箱宽 | -10～45℃ / 2.5℃ |
| EWMA 半衰期 | 14 天（336 小时） |
| 满置信有效样本数 | 40 |
| 预热样本 / 离群系数 / σ 下限 | 8 / 4.0 / 0.3℃ |
| 稳态斜率门 | 环境 10℃/h、冷凝 20℃/h |
| 预警余量 / 超限余量 / 迟滞 | 2.0℃ / 4.0℃ / 0.5℃ |
| 超限去抖 / 持续告警周期 | 60 秒 / 300 秒 |
| 传感器陈旧阈值 | 120 秒 |
| 值班轮换周期 | 7 天 |

上线建议：默认参数先以 `learned` 口径只观测不切机一周（日志比对人工基线），
确认残差分布后再放开自动并机；参数随 `evap.config` 持久化，调整动作本身也进审计。
